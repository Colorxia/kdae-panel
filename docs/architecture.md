# 架构与兼容策略

## 系统边界

```text
浏览器
  │ HTTPS / HTTP
  ▼
kdae-panel
  ├── 认证与会话：SQLite + Argon2id
  ├── 配置事务：validate、备份、原子替换、回滚
  ├── dae 适配：调用公开 CLI
  ├── 服务管理：systemctl
  ├── 日志与连接活动：journalctl JSON、/proc socket 表
  ├── 版本与 Geo 管理：GitHub Release / Actions
  ├── 网络探测：ICMP / TCP
  └── 定时任务：订阅刷新、Geo 更新
        │
        ▼
      dae.service
```

面板和 dae 是独立进程。面板不链接 dae 的内部包，不需要修改 dae，也不需要上游提供额外的 API。

## 外部契约

面板只依赖以下接口：

| 契约 | 用途 | 变化风险 |
|---|---|---|
| `dae --version` / `--help` | 版本与命令能力 | 低 |
| `dae export outline` | 动态配置结构 | 低 |
| `dae validate -c` | 校验候选配置 | 低 |
| `dae reload` / `suspend` / `sysdump` | 应用配置、暂停、诊断 | 低 |
| `.dae` 入口配置 | 配置的唯一真实来源 | 中 |
| systemd 单元、journald JSON | 生命周期、日志 | 低 |
| Linux procfs socket 表 | dae 出站 socket | 中 |

dae 版本管理另外依赖：

| 契约 | 变化风险 |
|---|---|
| GitHub Release 的 `dae-linux-<平台>.zip` 与 `.dgst` 命名 | 中 |
| GitHub Actions 接口的 `digest` 字段 | 中 |
| `nightly.link` 重定向服务 | 高（第三方） |
| 发布包里 `dae.service` 的默认路径 `/usr/bin/dae`、`/etc/dae/config.dae` | 中 |

dae 的内部对象、eBPF Map、Go 包和普通日志文本都不作为控制契约。

## 配置事务

保存在进程级互斥锁内串行执行：

```text
检查客户端提交的 SHA-256（乐观锁）
  → 在入口配置同目录写候选文件，继承权限并 fsync
  → dae validate -c 候选文件
  → 清理超出 50 份或 256 MiB 的旧备份
  → 旧配置写入 0600 备份
  → 原子替换入口文件并 fsync 目录
  → dae 运行中：dae reload <systemd MainPID>；未运行：留到下次启动
  → 失败时恢复旧配置
```

- 候选文件放在入口配置同目录，dae 的相对 `include` 路径才能正确解析。
- 乐观锁防止两个浏览器或外部编辑器互相覆盖。
- reload 显式传 systemd 的 `MainPID`，不依赖可能不存在的 `/var/run/dae.pid`。
- 配置保存、手动重载、订阅刷新、服务控制共用同一把控制锁。

用户手动保存的存档与自动备份使用相同格式的 `.dae` 文件，名称和备注存放在同编号的 `.meta.json` 里。恢复存档走完整的保存事务。

## 动态结构

`dae export outline` 返回字段、类型、默认值和说明。面板直接展示当前二进制返回的结构，不维护固定字段清单。

原始 `.dae` 文本始终是权威数据。面板不会把文本解析后重新生成，所以上游新增的语法不会被旧面板删掉。

## 可视化编排

全局设置、DNS、节点、订阅、分组和路由的可视化视图，由浏览器端的解析器（`web/src/utils/daeconf.ts`）从配置文本派生。它只做两件事：把文本切成节和条目用于展示，以及对被编辑的行或子块做定点改写。

它刻意不是完整的 DSL 解析器，因此遵守三条规则：

- **不重新生成配置。** 未编辑的行、注释、空行、无法识别的节，包括 CRLF 行尾，都逐字节保留。
- **拿不准就不改。** 一行有多个条目、条目跨行、落在块注释里时，不列为可编辑条目，交给该节的原文编辑。
- **不是安全边界。** 结果仍要通过乐观锁、`dae validate`、备份和回滚。解析器出错的最坏结果是 dae 拒绝候选配置，磁盘不变。

词法规则以上游 [`dae_config.g4`](https://github.com/daeuniverse/dae-config-dist) 为准，由 `web/src/utils/daeconf.test.ts` 锁定。

各部分的编辑方式：

- **全局设置**：字段支持情况和默认值来自 outline，不支持的字段会标记并禁止新增。只写用户实际修改的字段；未知、重复、跨行的声明保持原样并锁定。
- **DNS、路由**：各有简单模式和进阶模式，各自保存独立草稿，切换标签不写回。简单模式只在现有内容能完整往返时才默认选中，否则直接进入进阶模式，避免一次应用丢掉用户内容。
- **缺少 DNS 节时**，只在浏览器里生成默认草稿并标记为未保存，不会在打开页面时改写磁盘。

## 订阅

普通订阅的拉取、解析和缓存都由 dae 完成，面板只提供三件事：

- **离线缓存**：在 `https://` 和 `https-file://` 之间切换。带 `-file` 时，dae 把内容写入 `persist.d/<tag>.sub`，拉取失败时回退使用。
- **立即刷新**：执行一次 `dae reload`，dae 会借此重新拉取订阅。
- **定时刷新**：按间隔重复上一件事。拿不到控制锁就跳过这一轮并记录原因。

需要指定 User-Agent 的订阅由面板下载到配置目录的 `managed.d/`，在配置里以 `file://` 引用。Clash / Mihomo YAML 会转换成 dae 可读的格式，刷新失败时保留上一份有效缓存。

分组编辑器读取 dae 的 `persist.d` 缓存来列出订阅节点，写成 `subtag(来源) && name(节点)`，避免不同订阅里的同名节点互相误选。缓存解析只返回名称、协议和主机，不返回认证信息。

## dae 版本管理

### 安装事务

替换目标以 `dae.service` 的 `ExecStart` 为准，而不是 `KDAE_PANEL_DAE_BINARY`。两者可能不是同一个文件，替换错了会出现"事务成功但 dae 仍在跑旧版本"的假成功。

```text
下载并核对 sha256
  → 在目标同目录暂存（不用 /tmp：单元开了 PrivateTmp，且 /tmp 常为 noexec）
  → 新二进制自证：能运行、接受当前配置
  → 当前版本备份到暂存位
  → 原子替换
  → dae 原本在运行：重启并观察，确认 active 且 NRestarts 不再增长
  → 失败：恢复备份并把服务恢复到原状态
```

- dae 需要**重启**而不是 reload，因为 eBPF 程序要重新挂载。原本停止的 dae 不会被启动。
- 回滚点永远是"磁盘上当前这一版的前一版"。备份先写暂存位，事务结束时才决定保留还是丢弃，否则一次失败的安装会覆盖掉用户真正想回去的版本。
- "回滚失败"和"回滚成功但服务没起来"分开上报，不合并成一个布尔值。

### 本地版本库

下载过的二进制保存在 `dae-versions/`，每个版本是一个原子写入的自描述文件。文件名由来源、版本和构建变体做 SHA-256 得到，外部版本字符串不直接参与路径。切换时重新计算摘要，校验失败就重新下载。

本地版本与上游列表合并展示，所以已从 Actions 过期的构建、或上游离线时，仍可切换到本地已有的版本。

x86 优化构建按完整的 x86-64-v2 / v3 指令集判断，不会看到单个 `avx2` 标志就选 v3。虚拟机可能只透传部分 CPUID 特性，缺一项就回退到更保守的构建。

### 来源

- **官方**：版本是发布 tag，可以回到任意历史版本。
- **kdae**：分支没有发布，列出的是成功的 CI 构建，产物保留 90 天。面板会核对构建的仓库、事件、分支和工作流路径。

GitHub JSON 元数据在进程内缓存 10 分钟，相同请求合并，上游限流时沿用最近一次成功结果。Token 只加在发往 `api.github.com` 的首跳请求上，重定向时会被清除。

### 首次安装与卸载

机器上没有 dae 时，除二进制外还写入 Geo 数据、种子配置和 systemd 单元。它们来自同一个发布包、由同一个 sha256 覆盖；种子配置内置在面板里，不需要额外的下载源。

- **不会自动启动 dae。** 在一台正通过 SSH 访问的机器上，配置不当的透明代理会切断你自己的连接。种子配置不声明网卡，不接管流量。
- **不覆盖已有的配置和 Geo 数据。** 已有的服务单元也不覆盖，除非它与要写入的内容完全相同，或它的 `ExecStart` 已经指向要安装的文件。
- **冲突在动任何文件之前检查**，避免留下装了一半的机器。

卸载同样是事务：先确认安装记录、二进制摘要和单元路径都对得上，再停止服务、把文件移到暂存位、`daemon-reload`。任何一步失败都恢复文件、开机设置和运行状态。

## Geo 数据更新

Geo 管理与 dae 版本管理相互独立：只写数据文件，不碰二进制和服务单元。dae 升级也不会更新 Geo，没有这个功能时 Geo 数据会一直停在安装时的版本。

**来源模型是"每个文件各有出处"。** v2fly 把两个文件放在两个仓库，tag 也不同，因此界面如实分别显示两个版本，不编造统一版本号。

**两个来源的规则集不同。** 切换后 `geosite:` 的匹配范围会变，而 dae 照常通过校验和运行。界面只在切换时警告，沿用同一来源不重复打扰。

**写入位置按文件查找。** `geoip.dat`、`geosite.dat` 各自沿 `DAE_LOCATION_ASSET` → 配置目录 → `/root/.local/share/dae` → `/usr/local/share/dae` → `/usr/share/dae` 查找 dae 实际读取的那一份，缺失的才写到配置目录。写死目录会覆盖错位置或生成优先级更高的副本，之后更新就再也不起作用。被遮蔽的副本会在界面上列出。

**更新是跨目录事务**：各自同目录暂存 → 旧文件改名为回滚点 → 原子替换 → dae 运行中则 reload → 成功删除回滚点，失败把两份旧文件都放回并再 reload。两个文件必须同进同退，否则 dae 会拿两个版本的规则集运行，且不报错。

异常中断后留下的回滚点会阻止下一次更新，避免唯一的旧数据被覆盖。界面提供恢复和清理入口。

`dae validate` 不加载 Geo 数据，分类是否存在只有在启动或 reload 时才知道。面板会从 reload 输出和近期日志中识别 `not found in geoip.dat/geosite.dat`，在错误中指出缺失的分类。

自定义来源只接受公网 HTTPS。每次重定向都重新解析 DNS，连接前再检查实际地址，防止访问内网和 DNS 重绑定；不携带 GitHub Token。

## 观测边界

### 连接活动

连接活动有两个独立来源，不能合并：

**连接建立流水（journald）**

- 每次请求最多读取 500 行日志；内存中保留最多 2000 条、最近 24 小时，面板重启后重新积累。
- 官方 dae 和旧版 kdae 在 `info` 级别输出连接事件，kdae 从 `unstable-20260825.r1148.502d97` 起降到 `debug`。面板按版本和安装记录判断，只对确认的 kdae 接收当前 MainPID 的 `debug` 事件，避免把其他调试输出算成连接。
- 曲线把时间窗切成等长的桶（默认 60 个），空桶保留：曲线上的零表示"确实没有新建连接"。`seriesSince` 标出面板从什么时刻开始有数据，更早的部分是"不知道"，不是"没有流量"。

**socket 快照（procfs）**

- 通过 `/proc/<pid>/fd` 的 socket inode 过滤 `/proc/net/tcp{,6}`、`udp{,6}`，只统计 dae 进程自己持有的 socket。
- 页面可见时每秒请求一次轻量的 `/connections/snapshot`。结果缓存 800ms，多个标签页每秒也基本只扫描一次 `/proc`；MainPID 缓存 5 秒，避免每秒调用 systemctl。
- 同一 dae PID 保留最近 30 秒的样本：峰值取样本最大值，远端端点取样本的并集。PID 变化立即清空。
- 这仍然是离散采样，两次采样之间出现又消失的短连接看不到。

**为什么不能合并**：dae 透明代理的客户端侧留在 eBPF 数据面，没有 userspace socket；直连流量可能完全不产生 dae 的出站 socket；代理出站 socket 又会被多个客户端连接复用。procfs 只能回答"dae 现在连着哪些远端"，回答不了"某条日志里的连接是否还活着"。

### 延迟探测

- 公网地址发三次 ICMP Echo 取中位数。ICMP 不经过 dae 接管的 TCP/UDP，结果不受当前代理影响。ICMP 不通就返回无法测量，不用可能经过代理的 TCP 结果兜底。
- 内网、回环、链路本地地址测三次 TCP 握手，使用 `0x100` 绕行 Mark。
- 结果只代表节点主机的网络 RTT，不代表代理端口或协议可用，也不等于 dae 的健康检查。
- 首页会自动探测，因此服务端缓存最近结果（最多 256 个目标）。请求带 `maxAgeSeconds` 时复用足够新的结果，并返回 `probedAt` 让页面如实显示测量时间；手动点击探测（首页的重新探测、编排页的探测）不带该参数，每次都真实测量。

### 拿不到的数据

以下数据没有公开接口，面板不伪造、也不解析 dae 内部实现：

- 完整的实时连接表和逐条连接状态；
- 每条路由的命中统计；
- 精确流量和实时速率；
- 内部 DNS 缓存；
- 节点的真实健康状态，以及 `min_*` 策略当前选中的节点。

这些数据在上游是进程内 Go API（如 `control.SnapshotRuntimeStats`），供 dae-wing 这类进程内组件使用。如果 dae 将来提供稳定的只读接口，可以作为可选适配器接入。
